## Start the server

Make sure you have [uv](https://docs.astral.sh/uv/getting-started/installation/) installed, then:

<Tabs>
<TabItem value="ollama" label="Ollama (local)" default>

Install [Ollama](https://ollama.com/download), then pull a chat model and an embedding model and start the server:

```bash
ollama pull llama3.2:3b
ollama pull nomic-embed-text
uvx ogx go
```

The embedding model powers vector stores and file search. Without one, `ogx go` starts with the Responses, vector store, and file search APIs turned off.

</TabItem>
<TabItem value="openai" label="OpenAI">

```bash
export OPENAI_API_KEY=sk-xxx
uvx ogx go
```

The examples below use `ollama/llama3.2:3b`. Replace it with one of the `openai/...` model IDs the server lists.

</TabItem>
<TabItem value="docker" label="Docker">

Run a pre-built container image from [Docker Hub](https://hub.docker.com/r/ogxai/distribution-starter):

```bash
docker run -it \
  -p 8321:8321 \
  -v ~/.ogx:/root/.ogx \
  -e OLLAMA_URL=http://host.docker.internal:11434 \
  ogxai/distribution-starter
```

The container serves plain http without authentication. In the examples below, use `http://localhost:8321` and set `OGX_API_KEY` to any value.

</TabItem>
</Tabs>

:::tip Project setup
The `uvx` command above is great for trying things out. For a real project, install into a persistent environment:

```bash
uv init my-ai-app && cd my-ai-app
uv add ogx openai
uv run ogx go
```
:::

The server is now running at `https://localhost:8321`. You can use any OpenAI-compatible client.

OGX is secure by default: `ogx go` listens on https with a self-signed certificate and requires an API key. It prints three generated keys when it starts:

```text
  ✓ Simple authentication enabled
    Here are keys you can use for authentication:
      ogk_...
```

Copy one of them and export it in the terminal where you will run the examples:

```bash
export OGX_API_KEY=ogk_...
```

The keys change every time `ogx go` starts. For local experiments, `--insecure` makes the server listen on http and `--no-auth` turns off authentication.

## Verify it works

Before writing any code, confirm the server is healthy and models are registered:

<Tabs>
<TabItem value="curl" label="curl" default>

```bash
curl -k -s -H "Authorization: Bearer $OGX_API_KEY" https://localhost:8321/v1/models | python -m json.tool
```

</TabItem>
<TabItem value="python" label="Python">

```python file=./quickstart_verify.py#L7-
```

</TabItem>
</Tabs>

You should see output listing available models, for example:

```json
{
    "data": [
        {
            "id": "ollama/llama3.2:3b",
            "object": "model",
            "owned_by": "ogx",
            ...
        }
    ]
}
```

If the list is empty or the command fails, check the [Troubleshooting](#troubleshooting) section below.

## Troubleshooting

<details>
<summary><strong>Port already in use</strong></summary>

If you see `Address already in use`, another process is using port 8321. Either stop it or run on a different port:

```bash
uvx ogx go --port 8322
```

</details>

<details>
<summary><strong>Connection refused or connection error</strong></summary>

If `curl` returns `Connection refused`, the server has not finished starting. Wait a few seconds for model registration to complete, then try again. Check the terminal where you started the server for errors.

If the Python client raises `APIConnectionError`, check that `base_url` starts with `https://`. `ogx go` only listens on http when started with `--insecure`.

</details>

<details>
<summary><strong>Authentication required</strong></summary>

If the API returns `Authentication required`, the request is missing a valid API key. Export one of the keys printed by the running `ogx go`:

```bash
export OGX_API_KEY=ogk_...
```

Keys from an earlier run stop working when the server restarts.

</details>

<details>
<summary><strong>Responses API returns Not Found</strong></summary>

If `client.responses.create` fails with `Not Found`, look for this line in the `ogx go` output:

```text
  ✗ No embedding model detected — vector stores, file-search, and responses disabled.
```

Pull an embedding model and restart the server:

```bash
ollama pull nomic-embed-text
uvx ogx go
```

To use a different embedding model, pass `--default-embedding-model PROVIDER_ID/MODEL_ID --default-embedding-dimension DIMENSION`.

</details>

<details>
<summary><strong>Model not found</strong></summary>

If the API returns an error about a model not being found, make sure you pulled the model first. For Ollama:

```bash
ollama pull llama3.2:3b
```

Then restart the OGX server. You can verify available models with:

```bash
curl -k -s -H "Authorization: Bearer $OGX_API_KEY" https://localhost:8321/v1/models
```

</details>
